ml sends and fetches shares from the terminal. It uses the same 5-character codes as this page, so you can send from a server and open the code on your phone, or the other way round. ml clip sync also keeps one clipboard on all your computers; see Shared clipboard below. ml is on crates.io. With Rust installed, run: 
cargo install medialinker-cli
This builds ml from source and puts it in ~/.cargo/bin. Run the same command again to update. ml send prints the code. In a terminal it also prints a QR code and a link to this page, so a phone can open the share straight away. 
ml send photo.jpg              # share a file
ml send "meet at 6"            # share some text
ml send notes.txt --text       # send the name as text
ml send video.mp4 --ttl 7d     # 1h, 24h (default) or 7d
ml send report.pdf --no-qr     # leave out the QR code
Pipes With nothing to send, or -, ml send reads stdin. Text is sent as text; add --name to send it as a file. 
cat log.txt | ml send                    # a log, as text
journalctl -n 200 | ml send --ttl 1h
tar cz project | ml send -n project.tgz  # stdin as a file
CODE=$(ml send build.zip)                # stdout gets only the code
 ml get prints text, or saves a file in the current directory. It never overwrites a file unless you pass --force. 
ml get K7QX2                   # print text or save file
ml get K7QX2 -o out.jpg        # save under another name
ml get K7QX2 -o - | less       # write to stdout
 Add --encrypt (-e) and ml encrypts the share on your machine before it uploads it, with AES-256-GCM and a fresh key. The server only stores ciphertext and never sees the key, the file name or whether it's text. Instead of the bare code, ml send prints CODE.KEY, and the link and QR code carry the key after the #, which browsers never send to the server. 
ml send -e taxes.pdf             # prints K7QX2.3q9Vh…
ml get K7QX2.3q9Vh…              # decrypt with the key
ml get 'https://…/?code=K7QX2#k=3q9Vh…'  # or the whole link
ml get K7QX2 --key 3q9Vh…        # or the key on its own
It works both ways with this page: turn on End-to-end encrypt when sending here and ml get the link, or open a link from ml send -e in a browser. The code on its own can't open an encrypted share, so pass on the link or CODE.KEY. Encryption is off unless you ask for it. ml clip sync keeps one clipboard on your computers for as long as it runs. Copy text, an image or files on one and paste them on the others; copied files arrive as real files, so Ctrl+V in a file manager pastes them. The first device starts a room and shows a pairing code and a QR code; the others join with the code. 
ml clip sync                 # first device: prints K7X-42PQ
ml clip sync K7X-42PQ        # every other device
# press Enter in a running sync for a code for one more device
Nothing is saved: the room lasts one session. When any computer stops syncing (Ctrl+C, closing the terminal, a restart), the room ends on every device, and you pair again next time. Sleep and network drops don't count; devices reconnect by themselves. End-to-end encrypted: the code sets up a key that only your devices hold, so the server relays ciphertext it can't read. Files and folders up to 100 MB. On a phone, scan the QR code or open the shared clipboard page to copy and send by hand. ml completions prints a completion script for bash, zsh, fish, PowerShell or elvish. 
# bash
ml completions bash > ~/.local/share/bash-completion/\
  completions/ml
# zsh (with fpath+=~/.zfunc in .zshrc)
ml completions zsh > ~/.zfunc/_ml
# fish
ml completions fish > ~/.config/fish/completions/ml.fish
# PowerShell
ml completions powershell >> $PROFILE
 ml uses https://medialinker.noecore.com unless you tell it otherwise. To use this server, save it once: 
ml server {{ server }}
ml server on its own shows the saved server. --server URL or the ML_SERVER environment variable override it for one command.
